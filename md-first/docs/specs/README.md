## Configuration

Configure md-first in the project root's `Cargo.toml`:

```toml
[workspace.metadata.md-first]
include = ["md-first/docs/specs/README.md"]
exclude = []
```

`include` and `exclude` use globs relative to the project root; `exclude` takes precedence, and each path is scanned once.
Only explicitly closed fenced code blocks marked with `out=path` are processed. `out` is relative to the project root; absolute paths and paths that escape the root are rejected.

## Dispatcher

```rust out=md-first/crates/core/src/dispatcher.h.rs
use std::path::{Path, PathBuf};
use crate::{Error, Preprocessor};

#[derive(Default)]
#[spec::private_fields]
pub struct Dispatcher {}

#[spec::header]
impl Dispatcher {
    /// Create an empty Preprocessor registry.
    pub fn new() -> Self;

    /// Each out uses the Preprocessor with the longest matching suffix.
    /// - error: the suffix is empty or already registered.
    pub fn register(
        &mut self,
        suffix: impl Into<String>,
        preprocessor: impl Preprocessor + 'static,
    ) -> Result<(), Error>;

    /// Read the configuration, generate and overwrite each out, and create parent directories as needed.
    /// Return project-relative output paths sorted by path.
    /// Each file begins with a DO NOT EDIT notice and source Markdown paths, deduplicated in input order.
    /// - error: configuration, read, lexing, or preprocessing failure; no matching Preprocessor for an out.
    ///   These errors leave all outputs untouched; I/O errors during writes do not guarantee rollback.
    pub fn generate(&self, project_root: impl AsRef<Path>) -> Result<Vec<PathBuf>, Error>;

    /// Regenerate in memory and compare file contents without writing any files.
    /// - error: generation fails, or an output file is missing or differs.
    pub fn check(&self, project_root: impl AsRef<Path>) -> Result<(), Error>;
}
```

## Preprocessor

```rust out=md-first/crates/core/src/preprocessor.h.rs
use std::path::PathBuf;
use proc_macro2::{Span, TokenStream};

/// # Examples
///
/// ```
/// use md_first_core::{Context, Dispatcher, Preprocessor};
/// use proc_macro2::TokenStream;
///
/// // 1. Define how blocks with the same out are combined
/// struct Merge;
/// impl Preprocessor for Merge {
///     fn preprocess(&self, blocks: Vec<TokenStream>, _context: &Context) -> TokenStream {
///         blocks.into_iter().collect()
///     }
/// }
///
/// // 2. Register the preprocessor for an output suffix
/// let mut dispatcher = Dispatcher::new();
/// dispatcher.register(".rs", Merge)?;
/// # Ok::<(), md_first_core::Error>(())
/// ```
pub trait Preprocessor {
    /// Receive all blocks for one out in a single call, sorted by project-relative document path,
    /// then by their order within each document.
    /// Each block is tokenized independently; delimiters must balance, but complete Rust items are not required.
    /// The Preprocessor decides how to parse and combine blocks and whether declarations across documents are valid.
    /// The returned TokenStream is serialized and written to out.
    fn preprocess(&self, blocks: Vec<TokenStream>, context: &Context) -> TokenStream;
}

#[spec::private_fields]
pub struct Context {
    /// Absolute path.
    pub project_root: PathBuf,
    /// Relative to project_root.
    pub out: PathBuf,
    /// `sources[i]` corresponds to `blocks[i]`.
    pub sources: Vec<BlockSource>,
}

#[spec::header]
impl Context {
    /// Use a span from `blocks[block_index]` to report an error at the original Markdown location.
    /// This generation fails without writing any outputs.
    pub fn error(&self, block_index: usize, span: Span, message: impl Into<String>);
}

#[derive(Clone, Debug)]
pub struct BlockSource {
    /// Relative to project_root.
    pub document: PathBuf,
    /// First line of code in the original Markdown, 1-based; use Context::error for precise diagnostics.
    pub start_line: usize,
}
```

## Rust header

`md_first_preprocessor::rust_header::RustHeader` combines blocks in input order; the command registers it for `.h.rs`.
Standard Rust syntax and attributes are preserved, subject to the following rules.

| Declaration | Rule |
| --- | --- |
| Struct fields | Explicit `pub`, except for fields generated by `#[spec::private_fields]`. |
| `#[spec::private_fields]` | Add a private `inner: TypeInner` field to a struct with named fields, passing through its generic arguments. The implementer defines `TypeInner`. An existing `inner` field is an error. |
| `#[spec::header]` | Methods in an inherent impl must be explicitly `pub` and end with `;` instead of a body. The declaration supplies the signature and Rustdoc; the generated body forwards to `method_name_impl` on the same type. |

Declaration:

```rust
#[spec::private_fields]
pub struct Counter {
    pub name: String,
}

#[spec::header]
impl Counter {
    pub fn value(&self) -> u64;
}
```

Generated:

```rust
pub struct Counter {
    pub name: String,
    inner: CounterInner,
}

impl Counter {
    pub fn value(&self) -> u64 {
        Self::value_impl(self)
    }
}
```

Forwarding preserves type and const generic parameters; `async` awaits the implementation's result, and `unsafe` calls use an explicit unsafe block.
Destructuring, `ref`, and `_` parameters forward the whole argument. C variadic methods cannot be forwarded automatically and are rejected in headers.

## Self-hosting validation

1. Build md-first from the committed generated code, then read this document to generate its own interfaces.
2. Rebuild md-first using those generated interfaces, then generate again from the same Spec.
3. Pass only if both builds succeed and the two sets of outputs are byte-for-byte identical.

Commit generated files alongside the Spec; CI must also check that the committed files match the generated output.
